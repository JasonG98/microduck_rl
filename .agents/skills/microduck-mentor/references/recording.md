# 学习记录规则与模板

## 文件职责和更新顺序

- `docs/learning/plan.md`: 稳定的课程范围, 前置与验收. 仅路线变更时改动.
- `docs/learning/progress.md`: 唯一当前状态索引, 存背景/偏好, 当前与最近课程, 能力证据, 复习与暂停项, 下一步.
- `docs/learning/sessions/`: 每次课程或学习管理的详细记录. 使用 `YYYY-MM-DD-session-NN-topic.md`; 管理记录使用 `YYYY-MM-DD-learning-topic.md`, 不占正式编号. 同日重名时加数字后缀, 不覆盖.
- 历史 `session-01.md` 与 `session-01-supplement.md` 继续有效. 当前课程编号从 progress 和历史标题共同确定. 同一课跨日可继续原文件并注明日期; 用户明确开新课时再分配新编号.

先读当前记录再补充已发生内容, 再更新 progress 的链接和接续点, 最后检查引用. 中断后发现索引落后于详细记录时, 依据较新证据修复. 管理/状态查询不伪造授课内容. 索引缺失时标注“根据历史记录重建, 掌握程度未验收”.

路径在持久文件中使用仓库相对路径或相对 Markdown 链接; 对外回复按客户端要求用绝对文件链接. 依赖源码记录包名, 版本和符号, 不固定某台电脑 `.venv` 路径. 复现需要时记录 Git revision 与相关未提交改动, 不把 `git status` 中无关工作归入本课.

## 会话模板

按实际内容裁剪, 不保留空模板栏位. 缺少结果写“待实践/待回答”, 不编造耗时, 分数, 指标或用户回答.

```markdown
# Session N: 本节主问题

- 日期: YYYY-MM-DD.
- 单元/小节: Ux.y.
- 状态: 进行中 / 已暂停 / 本节结束.
- 入口: 上次接续点或用户本次新目标.

## 本节实际讲了什么

职责和上下游关系, 关键解释与例子. 保留足够内容供新导师和用户复习, 不只写主题标签.

## 源码与证据

仓库相对路径 + 符号, 核对过的实现结论. 若与旧笔记矛盾, 写出纠正和来源.

## 练习与理解检查

题目/目标; 谁执行; 已执行命令及关键结果摘要; 用户回答的准确摘要; 尚缺什么.
状态区分: 已示范 / 用户已实践 / 待实践 / 待回答 / 可独立完成.

## 卡点与变化

原来的误解, 本次澄清, 仍未确认的部分. 掌握等级变化要有用户证据.

## 停在哪里, 下次做什么

具体未完成项, 是否等待用户回答, 下一小节与源码入口, 验证方式及理由.
```

若本节只是解释概念, 无实际命令或结果, 明确“本节未执行实践”. 追问的结论追加到同一节, 不能把新解释当成用户已正确复述. 不把所有聊天逐字复制进文档.

## 实验记录附加字段

U5/U6 或用户指定实战时才加, 不给普通阅读课强加实验报告:

- 假设和行为目标, 基线 run/checkpoint 标识, 代码版本/相关差异.
- 主要改动变量, 精确命令, seed/环境数/训练长度与当前硬件条件.
- 测试和 smoke 实际结果; 长训练是否真正执行.
- 评估命令, spawn, 随机化/噪声设置, 训练或推理动作模式, 样本/episode 数量.
- 指标定义和单位, 实测数值, 视频观察, 失败例子, 解释与局限分开.
- 产物相对路径/可用远端标识, 是否被 Git 忽略; 必要文字结果写进记录, 不只留临时链接.

不要记录访问令牌或凭据. 远端 ID 只保存当前实验需要的部分. 无模型或无法运行时写清楚限制, 不把阅读配置包装成实验复现.

## 选择下一步

优先用户当前目标与未解决困惑; 其次当前小节未完成动作; 再按 plan 前置关系选择下一小节. 用户明确搁置的项目不进入自动推荐队列. 掌握检查缺失时可安排短复述, 但不要阻断用户想继续的内容. 已有训练经验不因换电脑缺文件被清零.
