# Microduck RL 系统学习计划

> 修订: 2026-09-05. 面向有 CV 工程经验, 简单学过 RL 原理, 缺少 RL 项目实操的学习者.
> 目标: 理解项目结构和执行过程, 逐步具备定位问题, 修改环境, 验证行为和部署排演的能力.

最终项目目标 (用户于 2026-09-05 明确): 自己设计并训练一个有挑战性的新动作, 形成可复现的开源项目, 用于展示个人能力. 独立完成环境配置、奖励/终止、训练与评估, 复用 mjlab/PPO/BAM 基础设施. 基础单元与独立项目衔接, 不跳过项目结构与执行流学习.

当前保留三个候选: **月球漫步/滑步舞、走梅花桩/精准踩点、推箱子转弯并停进目标区 (Push-T)**. 用户尚未决定唯一最终项目、实施顺序或同时完成三个项目. 下一步比较各自的最小成功版本, 尚未启动专项实验或训练. 详见 [项目候选比较](sessions/2026-09-05-learning-project-options.md).

| 候选 | 课程应用方向 | 选题前需要厘清 |
|---|---|---|
| 月球漫步/滑步舞 | U2 足底摩擦与支撑; U3 动作风格定义; U4/U5 奖励、参考动作与评估 | 如何区分月球漫步、普通倒走和拖行; 是否需要模仿学习 |
| 梅花桩/精准踩点 | U2 单脚支撑与足部可达范围; U3 足目标及接触判据; U4/U5 平地踩点到踏块的课程 | 第一版落脚目标和指令接口, 支撑与碰撞可行性 |
| Push-T | U2 物体接触与推力; U3 物体目标/机器人平衡; U4/U5 长时序任务与泛化 | T 形物体参数、接触方式、位置/朝向成功条件, 是否分阶段加入视觉 |

上述是课程映射建议, 非已确定的实现方案. U6 均需核对部署接口和排演; 当前共享 61D 观测约束保持, 不把新增足目标或物体观测直接塞入现有 actor. 架构方案待单独设计.


## 如何使用

- 以 velocity 为主线, 按能力推进, 不设置固定四周期限. 每个单元可拆成多次短课.
- 先讲模块职责, 再沿真实调用链阅读, 最后做一个小验证. 不逐行通读全部 `mdp.py`.
- 每单元都有用户亲手完成的小操作; 导师先示范必要步骤, 再逐渐减少提示. 用户需要代做时记录执行者, 不计为用户掌握.
- 每次围绕一个主问题. 首次建议 30-45 分钟, 用户可缩短, 加深, 跳转或暂停.
- 先补工程结构, PPO/GAE 已讲内容按需回顾. 不重复用长训练证明命令能运行.
- 本文只维护课程范围; 当前状态和证据统一放在 [progress.md](progress.md), 不重复打勾.
- 旧笔记保留在 [Session 1](session-01.md) 和 [补充](session-01-supplement.md). 历史说明不替代当前源码与 [AGENTS.md](../../AGENTS.md).

## U1 项目地图与入口

前置: 能运行 Python, 认识配置和训练脚本. 已有 smoke/长训练经历可直接使用.

- U1.1 职责边界: 本仓库提供机器人与任务; mjlab 组织环境和仿真; rsl_rl 负责 PPO; MuJoCo/MuJoCo Warp 负责物理; BAM 建模执行器. 对照 CV 的模型, 数据管线和训练框架, 说明 RL 数据由交互产生.
- U1.2 启动链: `pyproject.toml` 脚本与插件入口 → `train_cli.py` → mjlab 训练入口/插件加载 → `tasks/__init__.py` 注册 → cfg/runner 加载. 按实际代码确认调用顺序.
- U1.3 配置如何成为对象: velocity 基础配置, Microduck 工厂覆盖, play 配置和 RL 配置分别控制什么. 区分配置声明与运行中的 Manager 对象.

源码入口: `pyproject.toml`, `src/mjlab_microduck/train_cli.py`, `src/mjlab_microduck/tasks/__init__.py`, `make_microduck_velocity_env_cfg`, `MicroduckRlCfg`. 依赖源码从当前安装环境定位, 不固定某台电脑的 `.venv` 路径.

小实践: 找到 `Mjlab-Velocity-Flat-MicroDuck` 的环境和 RL 配置, 在临时配置副本或 CLI 中覆盖一个已理解的字段 (如 num_envs), 读取最终解析配置验证值确实变化. 保留修改前后值与来源, 不启动训练、不改共享默认配置. 无 GPU 可完成配置级验证.

验收: 用户能指出“改命令范围/网络宽度/初始姿态”各从哪里进入, 并解释本仓库没有重新实现整个 PPO 的原因.

## U2 机器人与仿真

前置: U1 职责边界.

- U2.1 模型词汇: body, joint, actuator, geom, site, sensor, 自由基座; qpos/qvel 的含义与维度不必相同.
- U2.2 项目映射: MJCF 场景/机器人文件, `HOME_FRAME`, `EntityCfg`, 主动与 `passive_*` 关节, 为什么不能对所有模型硬编码关节索引.
- U2.3 动作执行: 关节目标, BAM 电压控制与摩擦; 策略 50 Hz, 物理 200 Hz, decimation=4 的关系. 用实际配置核对这些值.

源码入口: `src/mjlab_microduck/robot/microduck_constants.py`, `src/mjlab_microduck/robot/microduck/` 中当前任务使用的 XML, `src/mjlab_microduck/actuator/friction_dr_bam.py`.

小实践: 用 CPU MuJoCo/BAM 列出舵机与传感器; 从稳定姿态对一个关节施加小幅目标变化, 记录目标、实际关节位置、执行器力矩、倾角和接触. 解释目标与响应为何不同; 不绕过 BAM. 若本机不能执行, 先完成静态映射, 动态验证记为待实践.

验收: 分清关节状态, 控制目标和实际力矩, 解释一帧策略动作期间物理仿真做了什么. 此时不要求推导 BAM 全部公式.

## U3 环境交互与基础评估

前置: U1 配置对象, U2 状态与执行器.

- U3.1 Command 与 Observation: 速度/头部/身体指令来源, 61D actor 布局 (48D 本体感知 + 13D 指令), critic 特权观测, 噪声与归一化的区别.
- U3.2 Action 与物理: 14D 输出如何缩放和偏移成关节目标, 上一步 action 如何回到观测. 用实际 ActionCfg 验证, 不默认输出就是力矩.
- U3.3 Reward 与 Termination: 沿速度跟踪, 姿态, action-rate 三项追踪原始返回值, 权重和时间缩放. 区分 terminated 与 truncated.
- U3.4 Event 与 Curriculum: startup/reset/interval, 并行环境独立 reset, 运行中 Manager 配置, 非累积 DR, 按环境步变化的课程. 按当前实现确认调用时机.

- U3.5 训练前的评估: 固定命令/初始条件/随机化与种子, 测速度误差、跌倒和接触, 同看视频与数值. 把任务成功判据与优化奖励分开, 不用总奖励替代行为质量.

源码入口: velocity 配置的各个 Manager 区域, 对应 `mdp.py` 函数, mjlab 的 `ManagerBasedRlEnv.step` 与 reset 路径.

小实践: 先预测 obs/action 布局, 再用已有 checkpoint 采集短 rollout, 对照观测、动作、分项奖励与 done, 追踪 reset. 固定静止/前进/转向条件形成一个小评估脚本或命令及结果表, 作为 U4 的训练前基线. 缺 checkpoint 时可验证环境数据流, 但策略行为评估保持待完成.

验收: 串起 `指令/状态 → obs → policy → action → BAM/物理 → reward/done/新 obs`, 说明随机命令与策略动作随机采样的区别.

## U4 短训练闭环与受控实验

前置: U3 transition 数据流与可重复评估. PPO/GAE 用复述检查, 不默认重新完整授课.

- U4.1 一次迭代: N 个环境各收集 24 个控制步, buffer, bootstrap/GAE, mini-batch/epoch, 更新与日志. 区分物理步, 环境步, episode, iteration 和总样本数.
- U4.2 Actor/Critic 与训练/推理差异: 分布采样 vs 确定性推理, 观测归一化, 损失与行为表现不能互相代替.
- U4.3 实验复现: 保存配置, 代码版本和未提交 diff, seed, checkpoint, optimizer/课程恢复, 本地日志与 wandb. 按实际 CLI 和 runner 确认恢复了什么.

- U4.4 受控修改: 提出假设, 保留原始基线, 一次改变一个主要变量; 核对奖励符号、时间缩放与实际贡献. 先适用 CPU 检查及 64 环境/5 迭代 smoke, 再按实际吞吐制定短训练预算.
- U4.5 结果解释: 同评估条件比较基线与变体, 区分训练预算不足、随机性、配置错误和假设不成立; 单种子只作初步证据.

源码入口: `MicroduckRlCfg`, 当前安装的 mjlab runner/wrapper 与 rsl_rl PPO/storage/model; 真实 run 的 `params`, 事件日志和 checkpoint 信息.

小实践: 用已有 run 识别配置与课程来源, 随后由用户完成一次 smoke、短训练、保存、重新加载和 U3 评估闭环. 对已理解的奖励或命令采样参数做单变量实验, 明确从头训练还是微调, 基线与变体使用可比初始化和预算. smoke 只验运行链, 不要求 5 轮学会动作. GPU 不可用时先读已有产物, 训练实践记为待执行.

验收: 计算 N×24 采样量, 区分课程到终点与任务已学好, 说明如何准确加载某次训练结果.

## U5 独立任务设计与项目实现

前置: U2 物理基础、U3 评估、U4 训练闭环. U3 后可比较候选并探索专项, 不要求同时学习三条分支; 正式新任务训练需完成前置实践.

- U5.1 最小任务定义: 用户写清起始状态、允许动作/接触、目标输入、成功/失败、超时及第一版范围. 区分机器人可行性与策略可学性, 先做接触、可达范围、负载等针对性物理验证.
- U5.2 观测与接口: 列出状态、actor 观测、critic 特权信息、指令、动作及各自来源/坐标系/单位. 核对部署是否获得这些信息. 当前 61D 合同不能偷偷扩维或改语义; 足目标/物体位姿的分层或接口演进方案必须单独设计, 不默认复用 velocity 就能表达任务.
- U5.3 奖励与探索: 分清优化奖励与独立成功判据, 检查符号/尺度/正则项、列出可刷分行为. 设计初始分布、课程与探索路线; 比较奖励塑形和参考动作方法, 按选题选用, 不预定某种算法必然有效.
- U5.4 实现: 选最近模板, 编写独立 cfg 与必要 MDP 函数、任务注册、cfg/函数检查、成功统计. 先做已知成功/失败状态的判据核对, 再 smoke, 逐阶段训练与录像评估.
- U5.5 实验: 建立合理基线, 保留未见条件, 做必要消融和多种子验证; 按失败类型诊断, 一次解决一个主要问题. 辅助初态成功不等于完整任务成功.

源码入口: `tasks/__init__.py`, `microduck_velocity_env_cfg.py`, `mdp.py`, `tests/` 与选题对应模型. 其他现有任务仅按需要比较, 不默认把坐站作为第二项目.

专项分支 (选择一个深入, 其余保留):

| 分支 | 补充内容 | 先做的小实践 | 后续项目目标 |
|---|---|---|---|
| 月球漫步/滑步舞 | 摩擦与支撑切换、周期/相位、动作风格、参考轨迹与模仿学习取舍 | 对一段候选动作标注承重/滑动阶段, 提出区分普通倒走和拖行的判据; 仿真核对足底滑动与支撑条件 | 学出可辨认的交替滑步, 测风格、稳定性和摩擦变化下的表现 |
| 梅花桩/精准踩点 | 世界/机体/足坐标系、基础正逆运动学、单脚支撑、目标条件化与地形课程 | 计算/显示足位置及目标误差, 检查少量目标的可达与支撑条件 | 先完整平地按序踩点, 再低矮踏块与变化步距, 评估落脚误差和连续成功率 |
| Push-T | 平面位姿与角度误差、接触/摩擦、物体操作和自身平衡、长时序探索 | 测轻物体的可推动/转动条件及机器人响应, 可先用真值位姿隔离感知问题 | 将 T 形物体推到指定位置和朝向, 再测试初态/物理参数泛化; 视觉作为扩展 |

上述是待实践路线, 不是已验证能力或已选定具体参数.

产物与验收: 用户完成一份任务定义、物理验证记录、可运行新环境及实验报告, 能说明每个主要设计的作用、替代方案和失败模式. 导师协助调试, 用户承担核心设计与实验解释; 不要求重写 PPO. 最终效果依实际 rollout 判断, 未达到目标时如实记录.

## U6 部署排演与开源交付

前置: U2 执行器, U3 接口, U4 正确加载策略.

- U6.1 checkpoint → 项目导出路径 → ONNX: 烘焙归一化器, 核对输入输出与动作约定, 不手工转换 checkpoint.
- U6.2 CPU MuJoCo/BAM 排演: 61D 命令槽, 50 Hz 控制, 默认姿态, 延迟与训练条件对应; 明确排演与 GPU 训练仿真的不同之处.
- U6.3 sim2real: DR 覆盖范围与系统性传感器偏差校准; 进一步阅读 Backlash 时核对模型一致性及传感器/奖励视角.

- U6.4 开源交付: 写清依赖、训练/评估/导出命令、模型与配置版本、种子、已知限制和复现步骤. 提供基线/消融结果与成功/失败视频, 区分仿真和真机结果; 未真机验证不写 sim2real 成功.

源码入口: `src/mjlab_microduck/export.py`, `scripts/export.py`, `scripts/infer_policy.py`, `tasks/backlash.py`, 相关测试. Hub 发布和真机操作是另行指定的扩展实践.

小实践: 通过项目导出器生成 ONNX, 核对 61→14 接口和归一化, 固定命令排演; 缺 checkpoint 时先完成接口阅读, 执行保留为待实践.

验收: 解释 play 能运行为什么不等于部署一定正确, 定位观测/指令/动作/执行器约定. 从干净环境按文档复现一次模型加载与评估, 形成可供他人检查的项目交付; 发布操作另按用户实际授权执行.

## 学习记录与工程边界

- 按证据区分未开始, 已讲解, 已实践, 可独立完成, 待复习. 导师执行不算用户独立掌握.
- 无 GPU 可继续读源码/CPU 练习; GPU 不可用是环境限制, 不是能力退步.
- 长训练前必须先 smoke. 时长按实际硬件和吞吐估计; `max_iterations=1000` 是迭代数, 不是环境步, 不再承诺“约一分钟”.
- 不以新增 actor 维度作练习: 保持共享 61D 接口. 改为追踪已有观测项及其归一化/部署对应关系.
- 工程不变量以根目录 `AGENTS.md` 为准, 行为判断依据当前代码和实际 rollout.
- 用户暂时搁置的问题留在进度中, 不自动变成下一课或训练任务.
